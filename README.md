## 認識這個作品

### 📖 遊戲簡介

這是「佛光尋光記：三好之旅」的 AI 增強版本，結合了：

- **🎨 精美視覺小說風格**：完整的場景背景、角色立繪、對話系統
- **🤖 AI 語意判定系統**：使用 Google Gemini API 進行智能分析
- **📚 教育意義**：透過遊戲實踐「做好事、說好話、存好心」的三好理念
- **💎 收集系統**：三顆寶石等待你用真誠的行動點亮

### 🎯 遊戲流程

> 以下含劇情概覽，供老師與評審快速掌握全貌。

**序章：接受使命**　在新生訓練中，你遇見星雲大師的精神化身，獲得一塊空白石板，展開尋找三好之石的旅程。

**第一章：大一 - 做好事（善行之石）**
- 情境：同學找不到 AirPods Pro 很著急
- 任務：用實際行動幫助同學
- 學習：純粹的善意無需回報

**第二章：大二 - 說好話（慧語之石）**
- 情境：到課外活動組繳交企劃書
- 任務：展現禮貌與尊重的溝通
- 學習：語言的力量能建立溫暖連結

**第三章：大四 - 存好心（淨念之石）**
- 情境：畢業典禮上的感恩時刻
- 任務：發自內心的真誠祝福
- 學習：善念不是任務，而是生活態度

**結局：覺悟圓滿**　三顆寶石合一，領悟三好精神的真諦。

### ✨ 遊戲特色

**雙模式 AI 引擎**

1. **Gemini API 模式**（推薦）：使用 Google Gemini 進行語意分析，理解複雜的語境和情感意圖，提供個性化反饋。透過 ListModels 自動偵測可用模型，Google 更新或淘汰模型時無需改程式。
2. **本地模式**（備用）：基於正則表達式的語意匹配，無需 API 金鑰即可遊玩，適合離線環境。

**互動體驗**：不再是預設選項，而是讓你自由輸入、真實表達；AI 即時分析回答是否符合三好精神，並給予具體建議。

**視覺呈現**：6 個場景背景、16 個角色立繪、流暢的場景轉換動畫、寶石收集動畫效果。

### 🎓 給老師的判定說明

> 本段說明 AI 的判定機制與各章判準，供老師理解與引導學生之用。**刻意不提供標準答案**——遊戲的目的是讓學生真誠思考與表達，公布範例答案會讓學生改成背誦、失去反思意義。

**判定機制**

每章的關卡會請學生**自由輸入**自己的回應，由 AI（Gemini）依該章對應的「三好」面向評估回應是否展現出真誠與善意，並給予個別化回饋。沒有單一標準答案——同樣的善意可以有很多種表達方式，重點在**是否發自內心、是否具體**，而非用字是否華麗。

（若未設定金鑰，會改用本地的正則比對作備援，準確度較低，僅供離線體驗。）

**各章判準**

| 章節 | 三好面向 | AI 主要看的是 |
| --- | --- | --- |
| 第一章 做好事 | 身（善行之石） | 是否展現**主動幫助的具體行動**與同理心，而非冷漠、推託或嘲諷 |
| 第二章 說好話 | 口（慧語之石） | 是否展現**禮貌、尊重與感謝**的溝通，而非命令、敷衍或無禮 |
| 第三章 存好心 | 心（淨念之石） | 是否展現**真誠的善念與祝福**、不求回報，而非交易心態或冷淡 |

**引導學生的建議（不破梗）**

1. **鼓勵具體**：請學生描述「具體會怎麼做、怎麼說」，而非空泛一句話。
2. **重視真誠**：提醒學生真誠的語氣比漂亮的詞藻重要，AI 看的是心意。
3. **完整表達**：太簡短、語意不清的回答容易判定不通過，鼓勵把想法說完整。
4. **善用提示**：每個關卡都有「提示」按鈕，引導思考方向，但不會給答案。
5. **把重點放在討論**：判定通過與否不是目的，課後帶學生討論「為什麼這樣回應是三好的展現」才是價值所在。

## 自行執行與部署

### 線上試玩（已部署）

最快的方式就是直接開最上面的 [https://play.cornhsu.com/seeking-the-light/](https://play.cornhsu.com/seeking-the-light/)，無需安裝任何東西。以下兩種方式適合想跑「自己一份」的人。

### 自行部署到 GitHub Pages

1. 建立你自己的 GitHub 儲存庫
2. 上傳所有檔案
3. 在 Settings > Pages 啟用
4. 使用產生的網址存取

### 在本機執行

1. **取得遊戲檔案**
   ```bash
   git clone https://github.com/HSU-YU-MING/seeking-the-light.git
   cd seeking-the-light
   ```

2. **啟動本地伺服器**（請勿直接以 `file://` 開啟 `index.html`，會導致 fetch／CORS 失敗）
   ```bash
   # 使用 Python
   python -m http.server 8000

   # 或使用 Node.js
   npx http-server -p 8000
   ```

3. **開啟瀏覽器**：<http://localhost:8000>

### 🔑 API 金鑰設定

**取得 Google Gemini API 金鑰**

1. 前往 [Google AI Studio](https://aistudio.google.com/apikey)
2. 以 Google 帳號登入
3. 點選「Create API key」建立新金鑰
4. 複製金鑰（格式：`AIza...`）

> 免費方案不需要綁信用卡。`gemini-2.5-flash` / `gemini-2.5-flash-lite` 屬於免費方案的主力模型，本遊戲的判定請求量很低，免費額度通常綽綽有餘。

**在遊戲中設定**

1. 首次啟動遊戲時會提示設定
2. 輸入你的 API 金鑰（系統會自動清除貼上時夾帶的空白、換行等雜質）
3. 金鑰只會儲存在你自己的瀏覽器（勾選「記住金鑰」存 localStorage，30 天後自動清除；不勾選則只存當次瀏覽期間）
4. 系統會自動偵測這把金鑰可用的模型，無需手動指定
5. 也可以跳過設定，使用本地模式

**注意事項**

- ⚠️ **金鑰儲存位置**：金鑰僅存在你自己的瀏覽器，不會上傳到任何伺服器，也不會進入專案原始碼。
- 🖥️ **共用電腦請務必清除金鑰**：在學校公用機、教室電腦或任何共用裝置上使用時，**輸入金鑰時請取消勾選「在此裝置記住金鑰」**（金鑰只在本次瀏覽期間有效，瀏覽器關閉即清除），或在用完後到遊戲選單點「🔑 重新設定 API 金鑰 → 確定清除」。否則金鑰會留在該瀏覽器，後續使用者可能用到你的額度。也可直接使用無痕／私密視窗開啟。
- ⏳ **自動清理**：勾選「記住金鑰」時，金鑰會在 **30 天後自動清除**並要求重新輸入，避免長期殘留。
- 🔒 **金鑰安全**：請使用「你自己」的金鑰，不要把金鑰公開分享。本專案為純前端網頁，金鑰一律由使用者在網頁上輸入、只存在使用者自己的瀏覽器，**不會寫進原始碼、也不會上傳到儲存庫**。請勿將任何金鑰硬寫進前端程式碼後公開——任何人都能在瀏覽器讀到。
- 🔐 **建議限制金鑰**：可在 Google Cloud Console 將金鑰限制為僅能呼叫 Generative Language API，降低外洩時的風險。
- 🧹 **清除金鑰**：清除瀏覽器資料、或在遊戲選單點「🔑 重新設定 API 金鑰」，即可移除已儲存的金鑰。
- 🔄 **變更金鑰**：可在遊戲選單中重新設定（換金鑰時會自動清除模型快取並重新偵測）。
- 🔍 **資料用途**：免費方案的輸入內容可能被 Google 用於改善模型；若有疑慮請改用付費方案或避免輸入敏感資訊。

### 💻 技術規格

**前端技術**：HTML5（語意化結構）、CSS3（動畫、過渡效果、響應式設計）、Vanilla JavaScript（無依賴，純原生實作）。

**AI 整合**
- **Google Gemini API**：透過 ListModels 自動偵測並選用可用模型（偏好 `flash-lite` / `flash` 等免費額度友善的模型）
- **本地語意分析**：正則表達式模式匹配
- **Fallback 機制**：API 失敗時自動切換本地模式，並顯示實際錯誤原因（400 / 403 / 404 / 429 分別提示）
- **模型快取**：偵測結果快取 24 小時，遇到 404 會自動清除快取並重新偵測

**瀏覽器支援**：Chrome 90+、Firefox 88+、Safari 14+、Edge 90+、行動裝置瀏覽器。

**功能特性**：遊戲存檔系統（localStorage，單一存檔槽）、響應式設計（桌面/平板/手機，含 5 組 media query）、背景音樂／角色語音／音效、離線遊玩（本地模式，無需金鑰）。

### 🛠️ 開發者資訊

**修改故事內容**

編輯 `story.js`，所有故事節點都在 `STORY_DATA` 物件中：

```javascript
chapter1: {
    c1_1: {
        id: 'c1_1',
        background: 'images/教室.webp',
        characters: {
            center: 'images/女大學生.webp'
        },
        speaker: '旁白',
        text: '你的對話內容...',
        next: 'c1_2'
    },
    // ... 更多節點
}
```

**調整 AI 判定規則**

在 `story.js` 的 `aiChallenge` 中修改：

```javascript
aiChallenge: {
    prompt: '給玩家的情境與提問',
    hint: '詳細的提示線索',
    context: '提供給 AI 的情境背景（影響判定）',
    gemType: 'good_deed',   // 必填：good_deed / good_word / good_heart，決定成功時加哪一項分數
    validation: {           // 本地模式（無金鑰）時使用的正則判定
        positivePatterns: [
            /正面的正則表達式/,
        ],
        negativePatterns: [
            /負面的正則表達式/,
        ]
    }
}
```

> 注意：`gemType` 為必填，`showAIResult()` 會依它加分；若漏填，AI 判定成功時會出錯。`context` 會一併送給 Gemini，有助於更準確的判定。

**模型選用（已自動化）**

本版本**不再需要手動指定模型**。`game.js` 的 `resolveModel()` 會透過 ListModels 自動偵測金鑰可用的模型，`scoreModel()` 則依偏好挑選（`flash-lite` > `flash` > `pro`，偏好穩定版、版本越新越優先）。

若要調整偏好（例如改成優先用 `flash` 而非 `flash-lite`），編輯 `game.js` 中的 `scoreModel()` 評分權重即可。若要在 ListModels 失效時改變備用模型，編輯 `fallbackModel()` 的回傳值。

**新增寶石類型**

1. 在 `game.js` 的 `collectedGems` 新增項目
2. 在 HTML 的 gems-display 新增 slot
3. 在 CSS 新增對應樣式

### 🐛 疑難排解

**遊戲畫面一片空白**：確認所有檔案都在正確位置；檢查瀏覽器 Console 是否有錯誤訊息；使用 HTTP 伺服器而非直接開啟 HTML。

**API 呼叫失敗**：判定失敗時，畫面會直接顯示實際錯誤原因，可依此排查：
- **403**：金鑰權限不足或未啟用 Generative Language API → 到 [Google AI Studio](https://aistudio.google.com/apikey) 確認金鑰
- **404**：找不到可用模型（罕見，系統會自動重新偵測）→ 確認金鑰所屬專案有 Gemini 存取權
- **429**：已達免費額度上限 → 稍後再試，或改用自己的金鑰
- **400**：請求格式有誤 → 檢查網路或回報問題
- 其他：確認 API 金鑰格式正確（`AIza...`），仍可使用本地模式作為備用

**圖片無法顯示**：確認 images 資料夾結構完整；檢查圖片檔名是否與程式碼一致（含大小寫）；使用瀏覽器開發者工具查看網路請求。

**存檔無法讀取**：確認瀏覽器允許 localStorage；清除瀏覽器快取後重試；檢查是否在無痕模式（無法儲存）。
